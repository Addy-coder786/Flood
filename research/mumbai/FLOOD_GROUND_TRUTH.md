## ANSWER TO THE KEY QUESTION (up front)

**Yes, but only partially and only qualitatively-to-semi-quantitatively, and only well for ONE event class.**

There are two independent, verifiable pieces of usable ground truth, and they should be used **together**, each for a different purpose:

1. **Event-specific validation for 26–27 July 2005** — YES, at a *named-location* (not coordinate) precision.
   - Rainfall: IMD Santacruz automatic weather station recorded **944 mm in 24 hours** (ended 08:30 IST 27 July 2005); Vihar Lake recorded **1,011 mm**; Tulsi Lake **944 mm**. These figures, with hourly breakdowns at some stations, are published in the Government of Maharashtra's official **"Fact Finding Committee on Mumbai Floods" (Chitale Committee) report, 2006** — a citable, downloadable government document (see Sources table). VERIFIED — I fetched and read this PDF directly.
   - Flood observations: the same Chitale report narrates, by name, which roads/areas were submerged for 12–24+ hours: Milan Subway, Andheri Subway, Malad Subway, Dahisar Subway, Hindmata, King Circle, S.V. Road/Linking Road (Khar–Goregaon/Malad), Western Express Highway (Kalanagar–Goregaon), Eastern Express Highway (Sion–Kurla–Chembur), CST Road, LBS Marg, Dharavi, Bandra-Kurla Complex, Chunabhatti, Chembur, Ghatkopar, Sion, and ~200 km of submerged road length citywide. VERIFIED — read directly from the PDF.
   - **Spatial precision of this ground truth is NAMED ROADS/AREAS/LANDMARKS, not georeferenced points or polygons.** This supports only a **qualitative** check: "did the model produce flooding roughly where the historical record says it flooded," not a pixel-level or point-level hit/miss score.
   - A secondary, independent academic study (TERI, 2016 — see Sources) built a MIKE21 hydrodynamic model of this same event and validated it against **27 specific flood points with observed flood *levels* in metres**, sourced from "the Greater Mumbai Disaster Management Action Plan report and Fact Finding Committee report Vol 2," and reported a strong observed-vs-modelled correlation. This is an **existence proof that quantitative, point-level validation for this exact event has been done by others** — but I was not able to obtain the underlying 27-point coordinate/level table myself (see "What I could not verify" below). If we want the same quantitative rigor, we would need to request/extract that table from the TERI report's annexures or from the two government reports it cites.

2. **Spatial-pattern validation independent of any single event** — YES, at **polygon-level georeferenced precision**, using a **live, unauthenticated, official MCGM ArcGIS REST layer called "Flooding Spots"** (see Detailed Findings §1). This is the single best-precision ground-truth source found in this investigation: 937 real, georeferenced polygon features (UTM Zone 43N) with attributes for ward, address, affected road, flood depth, waterlogging stretch length, and population affected. It has **no rainfall-event timestamp** — it is a chronic/cumulative "known problem spots" inventory, not tied to a specific storm date — so it cannot validate a single event's hydrograph, but it is directly usable to check whether the model's simulated high-hazard/ponding zones **spatially coincide** with BMC's own officially mapped chronic waterlogging polygons. This is a real spatial hit-test, stronger than a news-anecdote list.

**Practical recommendation:** run the model against the 26 July 2005 rainfall (obtainable in principle from IMD Santacruz / Chitale report tables) and report a **qualitative match** against the named locations in the Chitale report, PLUS overlay the model's chronic-risk output against the MCGM "Flooding Spots" polygon layer for a **quantitative spatial-overlap metric** (e.g., % of the 937 polygons that fall inside the model's top-N hazard zone). Be explicit in all documentation that neither constitutes a rigorous depth/timing validation against a single georeferenced flood map — that product does not appear to exist publicly for Mumbai.

## Detailed Findings

### 1. MCGM's own georeferenced "Flooding Spots" GIS layer — the strongest single find

While briefly probing the MCGM ArcGIS server (`https://prsrvgisapp.mcgm.gov.in/server/rest/services`) for disaster/flood-specific layers (per instruction, keeping this brief since another worker covers drainage layers on the same server), I found:

- Root folders: `Admin, CEMETERY_MANAGEMENT, esri, ESTATE, mcgm, projmap, SOMobileApp, TRENCHING, Utilities`.
- `mcgm/MCGMGIS_Departments_Master_All_Layers` (MapServer) contains a "Disaster Management" layer group (id 210) with sub-layers: MGL Assets, Fire Stations, MCGM Offices, Hospitals, Police Stations, Temporary Shelters, **Flooding Spots (id 344)**, **Flow Level Sensor (id 345)**, Vulnerable Settlements, Mumbai Contour, Wards.
- Querying layer 344 directly (`.../344/query?where=1=1&outFields=*&f=json`) returned **937 real polygon features** with a genuine attribute schema: `NAME` (Area Name), `LOCATION` (address), `WARD`, `AFFECT_ROAD`, `DEPTH`, `STRETCH` (metres), `AFFECT_AREA`, `AFFECT_POPULATION`, `AFFECT_RAIL`, `AFFECT_ELECTRIC`, `NO_DE_WATER_PUMP`, `CREATED_DATE`, etc.
- Sample records (verified, quoted verbatim from the API response): "Devkabai Chawl" (Lal Bahadur Shastri Marg, Ghatkopar West, Ward N, depth 3.0, stretch 50m, affected population 850); "Garodia Nagar Sati Krupa shopping centre" (Ward N, depth 2.0, stretch 100m, population 1200); etc.
- Geometry is real: rings of UTM Zone 43N (EPSG 32643) coordinates in the vicinity of Mumbai (e.g. ~278,730 E / 2,110,329 N).
- `CREATED_DATE` on sampled records = epoch 1506430176000 ms = **26 September 2017**, consistent with the BMC's post-2017 "225/386 chronic flooding spots" remediation program reported in news coverage. Some entries are suffixed "(Delete)" suggesting the layer is actively maintained/edited and some records are stale or marked for removal — **treat currency with caution; this is not confirmed to reflect 2023–2026 conditions**, only that the schema and many records date from ~2017 onward.
- Access: **no authentication was required** — this is a standard public ArcGIS REST Feature/Map service, queried with a plain HTTPS GET (a browser User-Agent header was needed; default `curl` without one returned 403, likely a basic bot-filter, not real authentication).

This is, by a wide margin, the best-precision ground-truth source found: real polygons (not point anecdotes), with depth and affected-population attributes, direct from the civic authority responsible for storm drainage.

**Caveat:** this inventory has no per-record flood-date/event field — it cannot tell us "on 5 July 2024 this polygon flooded." It represents cumulative/chronic knowledge, likely built from complaint logs and site surveys over years, not a single storm's inundation extent.

### 2. The 26 July 2005 event — the one historical event with strong documentation

This is Mumbai's most thoroughly documented flood, and for good reason: 944 mm in 24 hours, a >200-year return period per the TERI report's own frequency analysis, city paralyzed, national news coverage, an official government inquiry. Verified facts:

- Rainfall: IMD Santacruz **944 mm/24h** (ending 08:30 IST 27 July 2005); Vihar Lake **1,011 mm**; Tulsi Lake **944 mm** (Chitale Committee report, read directly).
- The TERI (2016) hydrodynamic-modelling report independently used **IMD Santacruz hourly rainfall (14:30 26 July – 02:30 27 July 2005)** plus **BMC Andheri AWS 15-minute data** as model input — confirming that sub-daily rainfall time series for this event has been obtained and used by researchers before, though I did not myself verify a public, freely downloadable source for that exact hourly series (IMD data of this kind is often only available via formal request/purchase from IMD Pune; this needs follow-up if we want the raw series ourselves).
- Flood locations: named directly in the Chitale report (list reproduced in the "Answer" section above) — submerged for 12 to 24+ hours, ~200 km of road length affected, 93% of roads flooded per the TERI hydrodynamic simulation.
- A **digitized flood-extent map for this event exists in the academic literature** (cited via Gupta 2007, Urban Water Journal, and reproduced/adapted in at least one other paper found via ResearchGate) but I was not able to fetch the original map/paper myself (paywalled/blocked).

### 3. Later events (2017, 2019, 2020, 2021, 2024/2026) — noted but not deeply verified

Search results reference an August 2020 event with "313 flood locations identified" (GeoJournal ML paper) and multi-year crowdsourced Twitter analyses (ScienceDirect paper) covering "2018 to 2025." Both papers were paywalled/blocked (HTTP 403) on both their primary host and ResearchGate mirror, so **I could not verify the claimed location counts, spatial precision, or data availability beyond the search-engine-generated snippets** — these snippets are secondhand and should not be cited as confirmed facts without accessing the papers directly (e.g., via institutional access).

### 4. Satellite/SAR flood mapping — assessed as NOT street-level useful for Mumbai

- Bhuvan/NRSC's flood hazard service is described (per its own portal language, fetched) as relying on "cloud free post [event] datasets," i.e., optical satellite imagery that must wait for clear skies — a severe limitation during active monsoon flooding, when clouds are the norm. No Mumbai-specific street-level product was found or confirmed.
- Sentinel-1 SAR (the MDPI Mumbai paper, not directly accessible) operates at ~10 m native resolution and, as a general property of SAR flood mapping (not something this session verified specifically for the MDPI paper, since it could not be fetched), performs well for open standing water but poorly for water hidden under building overhangs, dense tree canopy, or narrow street canyons — exactly the geometry of most flooded Mumbai streets. **This should be treated as a well-established general limitation of SAR/optical satellite urban flood mapping, stated honestly as informed assessment rather than as something confirmed specifically for this MDPI paper**, which I could not read.
- **Conclusion: satellite-derived flood products, as currently found, are not fit for street-level validation in Mumbai.** They may be usable only for a coarse "was this general area wet" sanity check, and even that is unconfirmed without cloud-free imagery timed to the event.

### 5. iFLOWS-Mumbai — a real, credible, but not confirmed-public system

iFLOWS-Mumbai (launched 12 June 2020, a Ministry of Earth Sciences / NCCR / MCGM Disaster Management Dept. joint system) genuinely operates a dense 120-gauge rain network, a 20cm DEM, and ward-level flood forecasting — this is exactly the kind of system whose historical archive would be ideal ground truth. However, the overview document describes outputs as delivered to "DMD-MCGM" and "IMD-Mumbai," with a "Flood Atlas" dashboard — **I found no public URL for this dashboard or its historical archive, and cannot confirm public access.** This should be flagged for the team: worth one direct attempt (e.g., searching for a public iFLOWS-Mumbai dashboard URL, or an RTI request) but not something this session could confirm as usable.

## What Validation Is Honestly Supportable vs Not

**Supportable, with the evidence in hand:**
- A **qualitative** check for the 26–27 July 2005 event: "given ~944mm/24h rainfall input at Mumbai's actual gauge locations, does our model produce severe flooding at/near the named roads and areas the Chitale Committee documented as flooded (Milan Subway, Andheri Subway, Hindmata, S.V. Road, WE Highway Kalanagar–Goregaon, EE Highway Sion–Kurla–Chembur, Dharavi, BKC, etc.)?" This is a reasonable, defensible, citable check.
- A **quantitative spatial-overlap** check against the MCGM "Flooding Spots" polygon layer (937 features): what fraction of these officially-flagged chronic waterlogging polygons fall within the model's simulated high-hazard/ponding zones, under a representative heavy-rainfall scenario. This is a real, citable, georeferenced comparison — though it validates spatial pattern/risk-zone plausibility, not a specific storm's timing or depth.

**NOT supportable, and must not be claimed:**
- A point-by-point or pixel-by-pixel quantitative hit/miss score against a single georeferenced historical inundation map for Mumbai — I found no such public downloadable product (the closest, TERI's 27-point dataset, was not independently obtained; the Gupta 2007 digitized 2005 extent map was cited by multiple sources but not itself fetched).
- Any claim that satellite (Bhuvan/SAR) products provide street-level validation for Mumbai — the evidence points the other way (cloud dependency, coarse resolution, canopy/building occlusion).
- Any specific list of "known flooding hotspots" beyond what is directly attributable to the two verified primary sources above (Chitale Committee report; MCGM Flooding Spots GIS layer) — do not extend, generalize, or supplement this list from general impression or from the unverified paywalled papers.
- Currency of the MCGM Flooding Spots layer as of 2026 — it is real and georeferenced but its creation timestamp (~2017) and "(Delete)"-flagged entries mean it should be described as "an officially maintained chronic-waterlogging inventory, base year ~2017 onward, currency not independently confirmed," not as "current 2026 conditions."
